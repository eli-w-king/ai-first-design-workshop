Workshop settings

Checked against VS Code Insiders 1.148 and the docs. Not yet tested on a clean personal account.

These two experimental settings make Computer Use and Send Later available. They do not approve tools, start an automation or purchase anything. Install Insiders below if you haven't yet, then return here.

Use a backed-up merge in your Default Profile. Read the steps below before pasting; do not replace your whole settings file.

Entries for existing settings
  // (Experimental) (Changes permissions) (Can use credits) Offer desktop app control; you still activate and approve access.
  "chat.agentHost.computerUse.enabled": true,

  // (Experimental) (Can use credits) Show Send Later for a one-time prompt; nothing runs until you schedule it.
  "sessions.sendLater.enabled": true

Copy the entries above into your existing outer braces. For a blank file or {}, use the complete snippet below. Download the settings file.

Complete snippet for an empty settings file
Complete settings snippet
{
  // (Experimental) (Changes permissions) (Can use credits) Offer desktop app control; you still activate and approve access.
  "chat.agentHost.computerUse.enabled": true,

  // (Experimental) (Can use credits) Show Send Later for a one-time prompt; nothing runs until you schedule it.
  "sessions.sendLater.enabled": true
}

Add them without losing your settings

  1. Open the Command Palette: Shift+Command+P on Mac or Ctrl+Shift+P on Windows. Run Profiles: Switch Profile, note your current profile, then choose Default.
  2. Run Preferences: Open User Settings (JSON). Choose the user file, not Default Settings or Workspace Settings.
  3. Save a complete local backup as workshop-settings-before.txt, outside your repo. Don't share it; settings can contain private information.
  4. Paste the two entries inside the existing outer { }. Put a comma after the preceding entry if it doesn't already have one. Keep the comma between the two new entries. Don't add another pair of braces.
  5. If a key already exists, change its value to true instead of adding it twice. Note its previous value, or that it was absent.
  6. Save with Command+S or Ctrl+S. Resolve any settings warning, save your work, then quit and reopen Insiders for Computer Use.

A separate profile is not the undo route: the Agents window uses the Default Profile, while plugin access, saved automations and OS permissions need their own cleanup.

Undo it

  1. Stop workshop runs. Cancel pending Send Later requests in Automations, then disable or delete the workshop automation. Turning off a setting does not cancel accepted schedules.
  2. Run /computer off, restore its previous setting value, and restart Insiders.
  3. Revoke the related OS permissions if you no longer want access.
  4. In the same Default Profile user file, restore each value you changed. Delete only entries that were absent before and fix adjacent commas. Restore the whole backup only if no later edits would be lost.
  5. In Customizations > Plugins, remove the workshop plugin if you don't want it. Keep your earlier plugins and sources.

05

Try dictation once

On an Apple silicon Mac or Windows x64 or Arm64 laptop, select the microphone in the chat input. First use downloads an on-device speech model and asks for microphone access.

Say: Make the heading a little smaller. Stop the microphone and check the text. Dictation does not send the prompt until you choose to send it. You can delete this test text.

Audio recognition runs on-device by default on these desktop systems. Optional transcript cleanup sends the text to a model. Turn off optional transcript cleanup in Settings if you don't want that. Intel Mac? Typing is fine; you don't need an extra voice extension for tonight.

What this changes

Downloads a speech-recognition model and gives VS Code microphone access. Model-based transcript cleanup is a separate setting from on-device audio recognition.

How to undo it

Stop dictation, turn off built-in dictation in Settings, and revoke VS Code microphone access in your system privacy settings if you no longer want it. Disabling dictation does not delete the downloaded model.

Screenshot and mark up

Checked against VS Code Insiders 1.148 and the docs. Not yet tested on a clean personal account.

Try native Mark Up in the chat input first. You make the visual mockup; the agent changes the real interface from that image.

  1. Capture the real interface. Where offered, use Add Context (+) > Screenshot Window or Screenshot App Window.... You can also use the OS tools below.
  2. Attach the image to the current chat input: paste with Command+V on Mac or Ctrl+V on Windows, drop the file, or use Add Context (+) > Files. Confirm its thumbnail appears.
  3. Select the unsent image, then Mark Up. Use arrows, drawing, text or crop to show your change.
  4. Select Done, then send the image with your request. Ask the agent to change the actual code and inspect the working result.

Escape applies and finishes markup; it does not discard it. Select / Move handles added annotations, not the original screenshot's pixels. A cut-and-rearrange workflow still needs checking. Use PNG or JPEG with a model that supports images, and keep private information out.

If native capture or Mark Up is missing

macOS: use Shift-Command-5 or Shift-Command-4, then edit the thumbnail or open the image in Preview's Markup toolbar. Use SDR / PNG where the format choice is offered.

Windows: open Snipping Tool or press Windows logo key + Shift + S. Use its pen, highlighter, shapes and crop. Copy the edited snip with Ctrl+C or save with Ctrl+S.

Keep an original copy. Paste or attach the edited image, not just its filename. These fallback tools annotate and crop; a layered rearrangement of the original UI is not a checked workshop step.

What this changes

Adds an image to your prompt. Native app-window capture can request screen-recording permission; it does not activate Computer Use or grant app control.

How to undo it

Undo marks before finishing, or remove the unsent attachment and attach the original again. Delete only image copies you made. Revoke capture permission separately if you no longer want it.

Start and stop Computer Use

Checked against VS Code Insiders 1.148 and the docs. Not yet tested on a clean personal account.

  1. After applying the settings and restarting, open a Copilot chat on This Computer.
  2. Enter /computer on. First use downloads its plugin. On Mac, choose Set Up Computer Use and grant Accessibility and Screen Recording yourself. Recent macOS versions call the latter Screen & System Audio Recording.
  3. Use only the agreed harmless app task and public practice files. Check each access request.
  4. Enter /computer off to turn it off. Restore the old setting and restart if you no longer want the feature. Remove its OS grants in System Settings > Privacy & Security too.

Computer Use can inspect and interact with desktop apps. Activation persists across chats and also affects Copilot CLI on that computer. Removing the setting alone does not revoke OS access. Windows has its own setup flow and still needs a first-use rehearsal.

Screenshot markup is not Computer Use. You draw the mockup yourself. We may install one small tool together in the room; we'll explain the download, permissions and undo steps before you approve it.

Mode and permissions

Checked against VS Code Insiders 1.148 and the docs. Not yet tested on a clean personal account.

Interactive, Plan and Autopilot are modes in Copilot. Interactive does the task. Plan proposes an approach first; enter /plan and review it. Autopilot keeps working and auto-approves tools.

Manual, Assisted and Allow all are permission levels. Manual follows your existing approval rules, so it does not ask before every action. Assisted uses a model to assess calls and asks about those it does not approve. Allow all runs tools without confirmation.

New Worktree sessions always use Allow all. A worktree separates files, not access to your machine. None of these modes or levels is a sandbox.

Start in a regular folder with Manual permissions and use Allow Once where offered. Only choose broader access deliberately. The settings snippet does not choose it for you.

Basic controls

Checked against VS Code Insiders 1.148 and the docs. Not yet tested on a clean personal account.

Use the labeled menu choices first. These shortcuts assume default bindings and the current steer preference. Your existing settings can differ.

Send
Starts an idle request. Mac and Windows: Enter.
Add to Queue
Waits until the current response finishes. Mac: Option+Enter. Windows: Alt+Enter, with the steer default.
Steer with Message
Redirects after the current tool finishes. Mac and Windows: Enter, with the steer default.
Stop and Send
Cancels the request and immediately sends your new message. Use the Send dropdown; no dedicated shortcut confirmed.
Stop
Requests cancellation without another message. Mac: Control+Escape. Windows: Alt+Backspace.
Send Later
Schedules one prompt, not a recurring task. Use Send Later... in the Send dropdown or Chat: Send Later... in the palette. No dedicated shortcut.
Edit and resend
Edits an earlier request. Review what will be rewound first; it does not undo external actions. Enter on a focused request, then Enter to resend, on either platform.
Attach a screenshot
Paste the image, drop a file, or use + > Files. Confirm the thumbnail is supported. Mac: Command+V. Windows: Ctrl+V.
Mark Up
Select the unsent image, choose Mark Up, then Done. Enter opens a focused image. Escape applies and finishes markup, not discard.
Switch model
Use the input's model picker. It changes the next request, not the harness. Mac: Command+Option+period. Windows: Ctrl+Alt+period.
Plan
Enter /plan with the outcome, then review the plan. Mac: Command+period opens the agent picker. Windows: Ctrl+period.

If your default is queue, Enter and Option/Alt+Enter swap meanings. Stop does not undo completed actions or cancel every pending follow-up; inspect those separately.

Before using Send Later

Choose a delay or a date and time, and check this device's time zone. A preset schedules immediately. Local Send Later needs an awake computer and an available host; it does not wake your laptop.

Use Cancel Schedule and confirm the pending entry is gone, or manage it in Automations. Turning off the setting does not cancel accepted requests. If you're unsure a schedule was created, check before retrying. Scheduled runs can use credits and act later with the session's permissions.

Keep spending a choice

The workshop files are free. AI requests use your account's credits. Input, output, cached input and cache writes can all count; parallel sessions, retries and scheduled runs can use more.

  1. On GitHub, open Settings > Billing & licensing > Budgets and alerts.
  2. Review a Bundled AI credits budget of $0, with Stop usage when budget limit is reached selected if you do not want paid AI-credit overage. An alert alone does not stop usage.
  3. Check your usage in Billing & licensing. Open Licensing to review your plan and renewal date. The workshop code's redemption, card and renewal terms are still being confirmed.

That budget does not cancel a subscription renewal, cover provider API-key bills or cap separate Cloud compute, memory and storage. Check those separately before any Cloud work. Keep workshop requests routed through Copilot; you do not need your own provider key.

Stop work and review budgets if you reach your intended limit. Reducing a budget or canceling a plan does not erase charges already incurred. Enabling the two settings costs nothing by itself; sending or scheduling work can use credits.

GitHub Pages is public

Publishing a GitHub Pages site exposes its content to the internet. On a personal GitHub Free account, the repository used for Pages must also be public.

Before you publish, check the files, screenshots and history for names, personal information, client work, keys and private links. Deleting a file afterward does not remove copies other people may have saved.

You can unpublish Pages in the repository settings, but that cannot recall shared copies. Nothing in tonight's draft guide publishes automatically.
