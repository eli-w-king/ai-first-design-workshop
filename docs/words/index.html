GitHub and your files

The words you will see when saving, reviewing and sharing a change.

RepositoryCloneForkBranchCommitPushPullPull requestReviewMergeIssueGitHub PagesDeployWorktree
Repository

A project folder with its files and change history. A repository, or repo, can live on your laptop and have a shared copy on GitHub.

Official docs for Repository ↗
Clone

Download a working copy of a repository and its history. You can edit that local copy without changing the shared one until you push.

Official docs for Clone ↗
Fork

A copy of someone else's repository under your own GitHub account. It lets you explore or propose changes without editing their original.

Official docs for Fork ↗
Branch

A separate line of work inside a repository. Use one to try a design while keeping the main version unchanged.

Official docs for Branch ↗
Commit

A named checkpoint in your project's history. It records the changes you choose, with a short message about what changed.

Official docs for Commit ↗
Push

Send your local commits to a remote repository, often on GitHub. On a public repository, those files and their history are visible to everyone.

Official docs for Push ↗
Pull

Bring changes from a remote repository into your local branch. If you and someone else changed the same part, Git may need help combining it.

Official docs for Pull ↗
Pull request

A proposal to bring one branch's changes into another. It gives people a place to inspect the difference, discuss it and run checks before merging.

Official docs for Pull request ↗
Review

Inspect a proposed change and leave feedback or an approval. A review is not the same as merging, and an AI review does not replace checking the result yourself.

Official docs for Review ↗
Merge

Combine one branch's changes into another. Merging a pull request changes the destination branch and may trigger publishing.

Official docs for Merge ↗
Issue

A place to describe a task, bug or idea and discuss the next step. A clear issue names the problem and how you will know it is fixed.

Official docs for Issue ↗
GitHub Pages

Hosting for a website made from files in a GitHub repository. For our personal GitHub Free setup, the repository and the published site are public.

Official docs for GitHub Pages ↗
Deploy

Put a built version of your app where it can be used, such as a GitHub Pages site. A deployment is a separate step from saving a commit, and the live result still needs checking.

Official docs for Deploy ↗
Worktree

Another working folder for the same Git repository, usually on a different branch. It keeps parallel edits apart, but is not a security sandbox; VS Code worktree sessions always use Allow all.

Official docs for Worktree ↗

AI and agents

What does the thinking, what does the work, and what you give it.

ProviderHarnessModelAgentSessionPromptContext windowTokensCreditsPlan modePermissionsManualAssistedAllow allAutopilot
Provider

The company or service supplying a model, such as OpenAI or Anthropic. How you access that model determines which account pays for it.

Official docs for Provider ↗
Harness

The software that connects a model to files, tools and a workflow. Copilot, Claude and Codex are harness choices in supported VS Code sessions; changing the model does not change the harness.

Official docs for Harness ↗
Model

The AI you choose to interpret your request and generate a response. Models vary in speed, cost and strengths; availability depends on your account and harness.

Official docs for Model ↗
Agent

An AI working with tools toward a task, rather than only replying with text. Depending on its tools and permissions, it can read files, change code, use a browser and check its work.

Official docs for Agent ↗
Session

A unit of agent work with a conversation, a workspace and its own context. Give separate tasks separate sessions when they need different files or independent decisions.

Official docs for Session ↗
Prompt

The request you give the agent. Name the input, the result you want, what it must not change and how to check the result.

Official docs for Prompt ↗
Context window

The amount of material a model can consider at once, including instructions, conversation and tool results. It is not a promise that the model remembers every file or earlier detail.

Official docs for Context window ↗
Tokens

The pieces a model uses to read and generate content. Input, output and cached tokens can all contribute to the cost, at the selected model's rates.

Official docs for Tokens ↗
Credits

The unit GitHub uses for AI usage: one credit equals $0.01 USD. The same number of credits can cover different amounts of work depending on the model, context and task.

Official docs for Credits ↗
Plan mode

Ask the agent to research and propose a plan before it implements changes. Review the scope and checks before approving the next step.

Official docs for Plan mode ↗
Permissions

The approval rules for tool actions. In Copilot, Manual, Assisted and Allow all are permission levels; Autopilot is a mode that auto-approves tools. None is a sandbox.

Official docs for Permissions ↗
Manual

Actions not already auto-approved ask for your confirmation. Previous approvals and your settings still apply, so Manual does not mean every action stops to ask.

Official docs for Manual ↗
Assisted

A model assesses each tool call and asks you about calls it does not approve. That assessment can make mistakes; it is not a security sandbox.

Official docs for Assisted ↗
Allow all

Tool calls run without asking you to approve each one. VS Code worktree sessions always use this level, so understand the task and tools before choosing a worktree.

Official docs for Allow all ↗
Autopilot

A mode that keeps working, retries and answers blocking questions while auto-approving tools. It is a permission level in the Local harness, but a mode in the Copilot harness.

Official docs for Autopilot ↗

Make it fit your work

Reusable guidance, extra tools and places a session can run.

Custom instructionsSkillsPluginsMCP serversHooksCloudComputer UseIntegrated browserBYOKDictationVoice Mode
Custom instructions

Written guidance the agent should follow for a project or your work. An AGENTS.md file can hold project rules, but instructions are not an enforcement boundary.

Official docs for Custom instructions ↗
Skills

Reusable instructions and supporting files for a particular kind of task. A skill can guide a workflow and include scripts; read it before giving it access to your project.

Official docs for Skills ↗
Plugins

Bundles of agent customizations you can install together, such as skills, hooks or tool connections. Check the contents, because some plugins can run code.

Official docs for Plugins ↗
MCP servers

Programs that give an agent tools through the Model Context Protocol. Each server has its own access and setup, so review what it can read or change before connecting it.

Official docs for MCP servers ↗
Hooks

Commands that run at specific points in an agent workflow, such as before a tool call. They can change your machine, so treat them as code, not just advice.

Official docs for Hooks ↗
Cloud

A place for an agent session to run in a managed environment instead of on your laptop. It is an execution target, not a harness; access, tools and costs depend on the service and your account.

Official docs for Cloud ↗
Computer Use

Tools that let an agent inspect and interact with a desktop app. It needs separate activation and OS permissions in a supported local Copilot session; manually marking up a screenshot is not Computer Use.

Official docs for Computer Use ↗
Integrated browser

A browser tab inside VS Code for local HTML and web pages. Your tabs are shared with an agent only when you choose Share with Agent; agent-opened tabs use isolated sessions.

Official docs for Integrated browser ↗
BYOK

Bring your own key: connect a model using an API key from its provider. That provider bills the usage separately from Copilot, and an app subscription does not automatically include API credit.

Official docs for BYOK ↗
Dictation

Turn speech into text without automatically sending the prompt. Supported desktop systems recognize audio on-device after a model download; optional transcript cleanup sends the text to a model.

Official docs for Dictation ↗
Voice Mode

A spoken conversation with an agent that listens and replies aloud. It is separate from dictation, is experimental, and its availability and billing depend on the account and voice provider.

Official docs for Voice Mode ↗
